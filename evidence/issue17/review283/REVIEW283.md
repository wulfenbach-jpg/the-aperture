1. **The checked-in RED logs are not bound to the reviewed bytes.** `evidence/issue17/slice28/red-mutation-*.log` record `sha256 before mutation: 3cd1c4bf3230…` for `crates/core/src/engine.rs`, but the file at 38dc519 (worktree and git blob) is `7439a45c…` (the CRLF variant is `237b1c16…`, so it is a content difference, not line endings). The logs are timestamped 05:11 local, the commit is 05:29. The *property* still holds at head — my re-run of all three of their mutations against the committed bytes is RED (section 4) — but the retained logs cannot by themselves show it. Regenerating them at head would close the gap; not blocking.
2. `engine.rs:499-511` orders the printed 7b setter before *all* one-shot setters unconditionally, justified by "a printed static's timestamp is its permanent's arrival". Correct for this pool; a future mass setter created before the Druid entered (e.g. "each creature you control has base P/T X until end of turn") would be ordered wrongly. Worth a comment/test when such a card arrives.
3. The `enter_battlefield` recompute is global (all battlefield objects, and it also drops effects whose target has left). It runs inside a resolution; the whole workspace suite and every recorded replay digest are unchanged by it, so it is behaviour-neutral today, but it is a new global recompute point and deserves to stay documented as such.
4. `StaticAbility` now has two entries whose `text()` is the same printed sentence (one per layer). Any future tooling that assumes one static entry per printed ability will be wrong; the delta's own test pins `statics.len() == 2`, which is good.
5. `has_subtype` scans the source's static list on every subtype query (combat filters, target offers). Irrelevant at 144 cards, O(#statics) per query by design.
